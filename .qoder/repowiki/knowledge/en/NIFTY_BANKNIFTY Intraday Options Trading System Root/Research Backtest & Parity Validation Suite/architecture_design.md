The module is organized as a self-contained backtest layer under `research/backtest/` with four sub-packages:
- `engine/`: two parallel engines — `research_engine.py` (`ResearchEngine`) is a standalone clean-room reimplementation of entry/exit, ORB, feature building, VWAP, Phase55 filter, and ML thresholds; `researchengine.py` (`ResearchBacktestEngine`) is a thin parity wrapper that instantiates the live `LiveEngine` via a minimal mock context and delegates every decision to it for field-by-field comparison.
- `data/market_data.py`: loads 1-minute Bank Nifty OHLCV CSVs, validates OHLC invariants, and filters by date range.
- `tests/`: pytest suite using `unittest.mock`/`pytest.monkeypatch` to inject deterministic predictors and learners into both engines, asserting sizing invariants (qty multiple of 30), cost-model parity, exit triggers (STOP/TRAILING/TIME_EXIT/ML), and golden-trade scenarios from `golden_trades.py`.
- `results/trade_log.csv`: output artifact generated by `run_quick_backtest.py`, which dynamically imports `ResearchEngine` via `importlib.util` to avoid namespace conflicts and writes per-candle trades.
Dependency direction is one-way: this module depends on the sibling `engine/` and `ml/` packages but never modifies them; it enforces parity by reusing `engine.execution.cost_model`, `engine.execution.profit_manager.manage_position`, `engine.risk.risk_manager.compute_entry_stops`, and `engine.live_engine.LiveEngine` directly. The `wrapper.py` entry point exposes a `ResearchWrapper` used by golden-trade tests to simulate single candles against the live engine.
