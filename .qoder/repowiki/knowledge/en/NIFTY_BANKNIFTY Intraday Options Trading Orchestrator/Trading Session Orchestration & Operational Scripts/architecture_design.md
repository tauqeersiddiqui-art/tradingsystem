Each file in `scripts/` is an independent entry point with no shared Python package — they are invoked directly by cron, Task Scheduler, or manually. Process supervision is split across three cooperating pieces: `supervisor.py` polls a PID file (`data/.master_runner.pid`) every N seconds (default 15 s), restarts `master_runner.py` up to `SUPERVISOR_MAX_RESTARTS`, writes heartbeat snapshots to `logs/supervisor_status.log`, and stops itself after 15:40 IST; it sends Telegram alerts via direct `requests.post` calls rather than importing the notifier to avoid long-poll conflicts. `monitor_session.py` tails `logs/master_runner.log` and filters notable events into `logs/monitor_session.log`. `session_monitor.sh` provides a Bash-side watchdog that kills the process at market close (15:30 IST) and re-launches it if dead. Launch orchestration lives in `.bat` files: `setup_autostart.bat` registers two Windows Task Scheduler jobs (`TradingBot_Morning` at 9:10 AM, `TradingBot_Afternoon` at 1:30 PM) which call `start_trading.bat` / `start_trading_afternoon.bat` to kill stale processes and launch `supervisor.py` in a detached window. Data tooling is separate: `refresh_zerodha_data.py` pulls NIFTY 1m candles via `kiteconnect` in 60-day chunks, backs up the existing CSV before overwriting, and normalizes timestamps to `Asia/Kolkata`. Backtesting utilities (`backtest_timing.py`, `backtest_entry_quality.py`, `backtest_exit_tuning.py`) subclass `ScalpEngine.check_entry` to compare old vs new entry logic on fixed datasets.
