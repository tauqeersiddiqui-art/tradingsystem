The scripts form a loose operational layer around `master_runner.py` (the trading engine) with no shared Python package — each file is an independent entry point invoked directly by cron/Task Scheduler or manually. Process supervision is split across three cooperating pieces: `supervisor.py` polls a PID file (`data/.master_runner.pid`) and restarts the engine up to `SUPERVISOR_MAX_RESTARTS`, sending Telegram alerts via direct `requests.post` calls; `monitor_session.py` tails `logs/master_runner.log` and filters notable events into `logs/monitor_session.log`; `session_monitor.sh` provides a Bash-side watchdog that kills the process at market close (15:30 IST). Launch orchestration lives in `.bat` files: `setup_autostart.bat` registers two Windows Task Scheduler jobs (`TradingBot_Morning` at 9:10 AM, `TradingBot_Afternoon` at 1:30 PM), which call `start_trading.bat` / `start_trading_afternoon.bat` to kill stale processes and launch `supervisor.py` in a detached window. Data tooling is separate: `refresh_zerodha_data.py` pulls NIFTY 1m candles via `kiteconnect` in 60-day chunks, backs up the existing CSV before overwriting, and normalizes timestamps to `Asia/Kolkata`. `backtest_timing.py` is a one-off analysis script that subclasses `ScalpEngine.check_entry` to compare old vs new entry logic on a fixed Aug 19 dataset.
