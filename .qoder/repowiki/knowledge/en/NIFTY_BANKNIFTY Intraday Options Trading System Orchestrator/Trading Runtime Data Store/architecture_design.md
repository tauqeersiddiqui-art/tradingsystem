Flat file-based persistence rooted at `data/` with no database layer. Top-level JSON files (`runtime_state.json`, `system_health.json`, `.master_runner.pid`) hold in-memory session snapshots (PnL, positions, mode, latency) that are periodically flushed by the running process. `trades/trade_log_YYYY_Www.csv` is the append-only trade ledger per ISO week, recording entry/exit prices, PnL, R-multiple, ML probabilities, slippage, and exit reasons across SCALP and EXPANSION strategies. `diagnostics/journals/` and `diagnostics/shadow/` contain daily CSVs (`*_YYYY_MM_DD.csv`) of live journal entries and parallel shadow-strategy outcomes (BE2/BE3/TRAIL10), enabling post-session replay and strategy comparison; `diagnostics/session_version.json` pins the git commit, model mtimes, and config version for each session. `historical/` holds pre-loaded NIFTY/BANKNIFTY 1-minute full-day datasets consumed as reference series. `analysis/` and `analytics/replays/` are reserved output directories for post-session analysis and replay artifacts. There is no code here — this directory is purely a data contract consumed by the trading engine and analysis tools.
