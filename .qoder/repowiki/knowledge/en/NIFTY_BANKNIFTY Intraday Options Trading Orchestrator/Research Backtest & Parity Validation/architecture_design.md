The module is a leaf under `research/backtest/` with four sub-packages forming a one-way dependency on the sibling `engine/` and `ml/` packages:
- `engine/research_engine.py` (`ResearchEngine`) is a standalone clean-room reimplementation of entry/exit, ORB windowing, feature building (RSI, ATR, Supertrend, ADX, VWAP), Phase55 filtering, and ML thresholds; it delegates sizing, cost, risk-stop, and profit-management to `engine.execution.cost_model`, `engine.execution.profit_manager.manage_position`, and `engine.risk.risk_manager.compute_entry_stops`.
- `engine/researchengine.py` (`ResearchBacktestEngine`) is a thin parity layer that instantiates the production `LiveEngine` via a minimal mock context (`_create_context`) and delegates every entry/exit decision to `live_engine.check_entry` / `check_exit`, comparing results field-by-field per candle in `_run_day_parity`.
- `data/market_data.py` centralizes CSV discovery, datetime parsing, sorting, and OHLC invariant validation (`validate_ohlcv`) reused by both the quick runner and tests.
- `wrapper.py` (`ResearchWrapper`) adapts a live `LiveEngine` instance for single-candle golden-trade simulation, exposing `simulate_single_candle` with deterministic exit logic (`STOP`/`TARGET`/`TIME_EXIT`).
- `tests/` contains pytest suites (`test_parity.py`, `test_golden_trades.py`, `test_qty_lot_invariants.py`) that inject deterministic predictors/learners via `unittest.mock.patch('engine.live_engine.ChampionPredictor')` and assert sizing, cost-model, and exit-trigger parity.
- `run_quick_backtest.py` is the CLI entry point that dynamically imports `ResearchEngine` via `importlib.util.spec_from_file_location` to avoid namespace conflicts, auto-discovers an OHLCV CSV, and writes `results/trade_log.csv`.
Dependency direction is strictly inward: this module depends on `engine.config.config`, `engine.live_engine`, `engine.execution.*`, `engine.risk.*`, and `ml.*`, but never modifies them.
