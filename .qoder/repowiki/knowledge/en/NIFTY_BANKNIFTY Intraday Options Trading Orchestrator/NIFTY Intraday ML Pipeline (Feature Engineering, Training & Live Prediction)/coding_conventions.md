- Feature ordering is centralized in `feature_config.FEATURE_COLUMNS` and imported everywhere (dataset builder, trainer, predictor, feedback logger) so training and live inference share identical column semantics.
- Models are persisted as paired `.pkl` + `_threshold.txt` + `_features.txt` files under `ml/models/`, with thresholds loaded at predict time and feature names validated against the model's stored list.
- Deployment is gated: new models only overwrite champions if they pass AUC ≥ MIN_AUC, calibrated-prob std ≥ MIN_STD, and positive expectancy; otherwise they are saved as `*_candidate.pkl` leaving live champions untouched.
- Cross-validation uses `sklearn.model_selection.TimeSeriesSplit(n_splits=5)` with recency-based sample weights (post-2024 rows weighted ×3) rather than label-based weighting, applied consistently across LightGBM and CatBoost training paths.
- Live feature computation mirrors the offline pipeline exactly: `build_live_features` computes the same 36 features from rolling OHLCV windows and a pre-computed signal dict, with clipping bounds matching training (e.g., `supertrend_dist` clipped to ±0.05, `volume_ratio` to 0–10).
- Runtime safety wrappers return zeroed feature vectors or `None` predictions on exceptions (e.g., `_safe_build_live_features`, `ChampionPredictor.predict` returning `None` on missing/invalid features) instead of raising, keeping the live engine resilient.
