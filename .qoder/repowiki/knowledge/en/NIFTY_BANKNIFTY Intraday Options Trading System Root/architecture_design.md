The root is the sole process boundary for live trading. `login.py` performs a one-time Selenium+Edge (or headless Chromium via Playwright) OAuth flow to refresh the daily-expiring `KITE_ACCESS_TOKEN` into `.env`. `master_runner.py` is the long-lived supervisor that assembles every child subsystem at startup via `build_context()` (broker → `ExecutionEngine` → `TradingContext` → `LiveEngine` → `CapitalAllocator` → `IntradayMLLearner`) and `init_candle_builder()` (feeds historical NIFTY 1m CSV into `CandleBuilder`). The main `engine_loop()` drives the intraday cycle while an in-process `EngineWatchdog` thread monitors the engine thread and auto-restarts it up to `WATCHDOG_MAX_RESTARTS` times, reconciling open positions from `data/runtime_state.json` on each restart. All cross-child contracts are routed through a single `TradingContext` object passed between master, engine, ML, and data_store; children never reach into each other's namespaces directly. Operational state (paper/dry-run modes, retrain locks, Telegram throttling) is coordinated centrally here rather than delegated to children. GitHub Actions workflows under `.github/workflows/` (`trading_morning.yml`, `trading_afternoon.yml`, `trading_test.yml`) orchestrate CI-triggered morning/afternoon sessions by writing secrets into `.env`, running `login_headless.py`, invoking `master_runner.py` with `timeout`, and persisting `data/runtime_state.json` across jobs so the afternoon session resumes positions seamlessly. The `research-tests.yml` workflow runs parity tests against the research child to validate decision equivalence without touching production code.
