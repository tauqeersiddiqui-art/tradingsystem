The module is organized as a layered pipeline centered on `live_engine.LiveEngine`, which owns the per-cycle `step()` loop: it updates ORB state, feeds candles to an `IntradayMLLearner` for day-type classification, builds a 28-feature vector via `ml.feature_config.build_live_features`, queries a `ChampionPredictor` for CE/PE probabilities, and then runs a cascade of session/time gates (ORB build window, warmup, lunch filter, regime skip), structural confirmation (swing HH/LL), higher-timeframe alignment (5m/15m/30m SuperTrend + EMA20/50), pullback-entry tracking, trap-filter detection, side-block checks from the learner, and finally `_finalize_signal` which computes ATR-based stops/targets and enforces expected-PnL and spread/slippage guards. Exit logic delegates to `execution.profit_manager.manage_position`, which implements a cost-aware profit-lock ladder and drawdown exit; actual order placement lives in `execution.ExecutionEngine` (buy/sell, SL-M protective stop, fill polling, dry-run/paper mode). Cross-cutting concerns are isolated: `core.context.TradingContext` is the single DI container all modules read via `ctx.*` (no direct cross-imports), `config.Config` centralizes every tunable parameter behind `os.getenv`, `risk.risk_manager.compute_entry_stops` caps worst-case loss at 10 premium pts, and auxiliary packages provide analytics (`analytics/*`), diagnostics (`diagnostics/*`), portfolio allocation (`portfolio/allocator.py`), scalping overlay (`scalping/scalp_engine.py`), and intelligence filters (`intelligence/phase55_filter.py`). Dependency direction is strictly inward toward `core`, `config`, and `execution`; the live engine depends outward only on the external `ml.*` package and the broker abstraction exposed through `ctx.broker`.
